# 项目使用与维护指南

## 架构与目录

根目录 `run.py` 是统一入口，通过 `--experiment expert_only|joint` 选择实验。准备器构造数据视图，调度器负责短跑、训练预算、续训、评测及报告；训练和评测在独立子进程中调用现有 LeRobot 实现。

输入为任务语言、双路 256×256 RGB 图像和 8 维状态，输出为 7 维相对动作。模型预测 50 步动作块，现有评测每次只执行第一步，再根据新观测预测。LIBERO 使用 Panda，控制频率 20 Hz，每回合上限 220 步。

| 目录或模块 | 职责 |
|---|---|
| `configs/` | 两种实验的冻结策略、参数存储精度和默认运行参数 |
| `smolvla_experiment/common.py` | 实验上下文、路径保护、环境和联合微调 FP32 精度设置 |
| `smolvla_experiment/records.py` | 管理记录、评测协议、短时锁、原子更新、临时配置及逐步计时 |
| `smolvla_experiment/prepare.py` | 资源检查、数据划分、归一化统计、处理器及准备校验 |
| `smolvla_experiment/pipeline.py` | 命令解析、工作流调度、后台、预算、运行锁和成功后的短跑整理 |
| `smolvla_experiment/train.py` | 原生训练与续训、参数更新检查、训练／验证指标及 GPU 采样 |
| `smolvla_experiment/evaluate.py` | 原生仿真评测、回合长度记录和视频帧率对齐 |
| `smolvla_experiment/report.py` | 读取实验输入、统计与选模、管理记录更新、报告和 CSV 导出 |
| `smolvla_experiment/plots.py` | 接收已读取的数据，绘制 loss、成功率及策略对比图 |
| `experiments/` | 按实验隔离的数据视图、处理器、配置、来源和运行记录 |
| `resources/libero_assets/` | 两种实验共享的仿真素材 |
| `docs/` | 本指南、[实验结果与案例](results.md)、媒体及[参考论文](references/2506.01844v1.pdf) |

原始数据和基础权重通过相对符号链接指向 `lerobot/downloads/smolvla_libero/`，各实验的 `assets` 链接指向共享素材。程序只在缺失时创建输入链接，不通过共享链接写入。`ExperimentContext` 显式传递实验范围，写入时解析链接后检查边界，拒绝跨实验或指向共享输入、`lerobot` 的写入。

两种实验分别保留小型数据元数据、处理器、模型配置和环境快照。训练、验证划分相同：384 条训练轨迹／47,043 帧，48 条验证轨迹／5,927 帧；按任务留出末尾完整轨迹，归一化统计只取训练帧。

实验代码采用扁平的 9 文件结构：上述 8 个功能模块和一个 `__init__.py`。统一从根入口调用，内部训练／评测子进程分别使用 `smolvla_experiment.train`、`smolvla_experiment.evaluate`；旧的 `training.*`、`analysis.*` 模块路径退出使用，不保留兼容转发。

报告每次读取当前运行记录、指标 CSV 和原始评测各一份，复用输入完成统计、绘图、导出与恢复说明；对比运行同样复用已读取的划分和指标。绘图不读取管理记录或原始指标。最终写入仍在锁内重新读取最新记录，更新评测分区，保留同时发生的其他分区更新。

## 配置与精度

| 设置 | 动作专家 `expert_only` | 联合微调 `joint` |
|---|---|---|
| `train_expert_only` | `true` | `false` |
| `freeze_vision_encoder` | `true` | `true` |
| `train_state_proj` | `true` | `true` |
| 可训练参数／总参数 | 99,880,992／450,046,176 | 306,471,072／450,046,176 |
| 参数存储 | 原生 BF16/FP32 混合存储 | FP32 |
| 计算混合精度 | BF16 | BF16 |
| 默认 batch | 8，短跑 OOM 时可退至 4、2 | 8 |

新训练默认先短跑 200 步，再训练至 20k。学习率 1e-4，warmup 1000 步，余弦衰减至 20k 的 2.5e-6；每 1000 步保存完整检查点并使用固定 1000 帧做离线验证。修改新训练目标时，warmup 和衰减长度随目标调整；现有检查点续训恢复原调度器，不重建学习率计划。两轮正式历史实验均先训练至 20k，再追加 5k，seed 0、batch 8、无梯度累积。

联合微调最初的 200 步试跑虽有梯度，但部分 BF16 参数没有可测更新，因此在正式训练前终止。修复是在模型构造阶段、加载 safetensors 之前将参数存储转换为 FP32，再创建 AdamW；计算仍采用 BF16 autocast。修复后的短跑通过更新与冻结检查，正式训练从基础模型重新开始。该处理用于联合微调的训练、续训和评测，历史动作专家配置继续使用原生存储方式。两种精度策略分别在子进程中执行。

已有结果同时存在解冻范围和参数存储精度差异，不能将结果单独归因于解冻范围。

## 运行与恢复

使用现有 Python 3.12 Conda `lerobot` 环境，从根目录执行 [README 中的命令](../README.md#使用)。准备、训练、评测的模块启动代码供调度器调用；分析模块只作为内部函数使用。

- `--prepare-only` 校验现有离线资源，已完成的准备不会覆盖数据、统计和处理器。输入损坏或配置不兼容时直接报错。环境路径变化时应核对环境及 `libero_config/config.yaml`，不要删除准备记录来绕过校验。
- `--resume CHECKPOINT --additional-steps N` 从同一次运行的最新完整检查点续训，默认追加 5000 步。程序检查保存步数、配置、原始指标、运行记录和优化器／调度器／随机状态，拒绝过期检查点和跨实验恢复。原检查点配置不改，新目标通过命令参数传给原生训练器。续训不自动启动仿真。
- `--budget-s` 默认 28800 秒，累计短跑和训练循环；准备与仿真另计。接近时限时保存可恢复检查点后结束，失败或中断保留诊断。成功后可整理短跑产物，不自动删除未来的历史检查点。
- 每种实验使用自己的工作流锁。`--background` 后台运行并保存 PID，`--queue` 等待锁释放。启动信息位于实验记录的 `launcher`，状态位于 `activity`，后台日志为实验下的 `logs/pipeline.log`。两个实验共用 GPU 时需按可用显存安排运行。

工作流活动不是模型完成状态。模型编号和训练进度以对应运行的 `run.json` 为准；原有的两个旧工程入口及 `--resume-training` 已退出使用，统一使用 `--resume`。

## 评测与报告

默认评测为 LIBERO-Spatial 10 个任务×每任务 10 回合，固定初始状态 0–9、seed 0、256×256 图像、hard reset、相对控制、20 Hz、220 步上限、`n_action_steps=1`、10 次推理迭代，视频保存为 20 FPS。

`--evaluate-only RUN --checkpoint ...` 支持多个检查点；省略编号时选择最新保存模型。完整结果通过校验后跳过，不完整结果保留并报错。`--eval-batch-size` 支持 1、2、5、10，串行结果使用 `eval/025000/`，并行结果使用 `eval/025000_b5/` 等独立目录。改变 batch 会改变策略噪声分配，不同 batch 或 seed 的结果分别记录。

报告只从原始指标和逐回合结果复算，不启动训练或仿真：

| 报告参数 | 输出 |
|---|---|
| `--report-only RUN` | `REPORT.md`、训练／验证 loss 图、检查点成功率图 |
| 再加 `--compare-with OTHER_RUN` | 增加策略 loss 对比图 |
| 再加 `--export-csv` | 导出 `evaluation_summary.csv`、`per_task.csv`；若指定对比运行，再导出 `loss_strategy_comparison.csv` |

跨实验对比必须显式传入两个运行目录，验证数据划分和共同范围内记录步数一致，使用原始记录，不额外平滑。

报告输出匹配本次参数：省略 CSV 导出时移除上述三种旧派生 CSV；省略对比时移除旧对比图；旧性能综合图不再生成。清理仅处理已知的报告产物名称，保留用户放入目录的其他文件。原始 `train_metrics/`、`eval/` 不参与此清理。相同参数重复生成报告得到相同内容，不增加带时间戳的重复文件。

只有符合默认协议且完整完成 100 回合的结果参与最佳模型选择，同分取较早检查点。成功率使用逐回合 `successes` 复算，区间采用 95% Wilson 区间；最佳观测使用同批评测选模，并非独立测试成绩。平均回合长度包含失败回合。

## JSON 与 CSV 的用途

| 文件 | 生成过程和用途 |
|---|---|
| `metadata/experiment.json` | 准备及调度阶段维护：来源、素材、准备校验、最近活动和后台启动信息 |
| 每次运行的 `run.json` | 训练、续训及报告维护：配置、运行状态、计时、会话、预算、协议、选模与关键统计 |
| 数据划分、归一化和处理器 JSON | 准备阶段生成，训练与推理输入；原内容保留 |
| 模型、分词器及续训状态 JSON | 原生保存过程生成，每个完整检查点独立保留 |
| `eval/*/eval_info.json` | 仿真评测生成，保留逐回合成功、奖励、步数和恢复说明 |
| `train_metrics/train.csv`、`validation.csv`、`gpu.csv` | 训练期间记录的原始训练、离线验证与 GPU 指标 |
| `train_metrics/step_timing.csv` | 联合微调历史逐步计时迁移而来；后续训练使用专用追加接口记录 |
| 联合微调 20k 的 `episodes.csv` | 评测恢复过程的逐回合记录和证据 |
| 运行根目录的派生 CSV | 仅在报告显式导出时生成，可由原始结果重建 |

当前稳定状态共 132 个 JSON：113 个模型／分词器／续训／数据原生配置，11 个原始评测，4 个实验配置与划分，4 个管理文件。默认保存的 8 个 CSV 均属于原始指标或恢复材料；验证集指标是正式实验记录。

两个管理文件使用 `schema_version: 1`。实验记录分为 `provenance`、`assets`、`preparation`、`activity`、`launcher`；运行记录分为 `config`、`runtime`、`timing`、`sessions`、`budget`、`evaluation`、`probes`、`diagnostics`。选模只保存编号及必要说明，路径从运行目录推导；汇总保存关键统计、原始来源和本次实际导出引用，不嵌入逐任务数组、完整状态或计时副本。

管理记录各有独立短时文件锁，更新时在锁内读取最新版本，再原子替换，防止父子进程覆盖不同分区。工作流锁与记录锁职责分开。损坏或未知版本记录会明确报错，不以空内容覆盖。

准备校验版本为 4，检查实际准备产物及 `provenance`、`assets` 的规范化摘要，不把管理文件自身或活动状态纳入哈希。历史来源路径和当前素材路径分别保留。新训练使用临时原生配置 JSON，调用结束后清理；配置及失败诊断保留在管理记录中，检查点内原生配置不变。

## 历史计时与评测恢复

动作专家训练循环累计 4747.266 秒（79.12 分钟），未独立记录初始化后的全流程墙钟。联合微调两个阶段实际墙钟为 4604.234 秒和 1622.041 秒，合计 6226.275 秒（103.77 分钟），包含阶段初始化、验证和保存，不含隔夜暂停。两种口径分别保留。GPU 整卡采样峰值与 PyTorch 分配峰值分别报告，不跨采样空档推算能耗。

联合微调 20k 前 75 回合的成功结果由原日志累计成功率恢复，回合长度来自原视频；后 25 回合为续测。原视频未修改，前段原奖励未保存，整体 reward 统计留空。初始状态和 seed 延续原编号，策略噪声按已完成步数重建；原随机状态没有快照，不承诺与未中断运行位级一致，评测耗时部分由日志估计，不含隔夜暂停。

原始结果的 `recovery` 字段、该轮 `episodes.csv` 和 `recovery_source.log.gz` 继续保留，日志解压 SHA256 记录在原始结果中。删除普通历史日志不影响这份恢复证据。

### 实验代码扁平化
